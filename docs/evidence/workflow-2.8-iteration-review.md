# Implementation evidence: workflow 2.8

## Implementation findings

Inspection of the repository identified instructions that could encourage
completion by bookkeeping, transfer internal records into manuscript prose, or
confuse pattern checks with substantive assurance. Follow-up inspection found
contribution-phrase position rules, automatic adoption of role recommendations,
and method handoffs that ended at code and a methods paragraph.

The revision replaces those instructions in their execution paths. The shared
writing contract distinguishes findings, economic meaning, contribution, and
behavioral interpretation. All nine method-pack prompts reference that contract;
structural and noncausal work use the corresponding stage routes. Technical
method requirements remain in their selected packs.

## Recorded verification

- Initial implementation: 447 tests passed; runtime parity reported zero errors.
- Cross-method extension: 448 tests passed, including a routing test covering
  every method manifest in the repository.
- Numerical fault injection: a corrupted registry value fails against an
  independently specified source value; a valid control succeeds.
- Disclosure-location check: removing a required anchor fails, while a valid
  location does not require a prescribed contrastive phrase.
- Existing lifecycle tests retain failures for unresolved dependencies,
  incomplete closures, and deferred blocking remedies.
- Routing fault injection: a temporary pack with a valid shared-reference link
  succeeds; removing that link fails.
- Project and user runtime views resolve consistently to the canonical tree.

These are recorded maintenance results, not a new empirical replication. The
test sources are in `tests/test_registry_validator.py` and
`tests/test_workflow_contract.py`; see the repository README for environment
setup and test execution.

## Limits

Tests establish specified software behavior and reference routing, not the
truth of a claim, methodological correctness in every application, manuscript
quality, or reduced rework. The migration guide's examples are implementer-led
assessments. No independent manuscript cold read, empirical re-estimation,
historical PDF reconstruction, or submission certification was performed.
Method canons and estimation templates were not comprehensively revalidated.
